# نقشهٔ توسعه و معیار پذیرش

مرحلهٔ فعال مطابق درخواست مستقیم ۲۰۲۶-۱۰-۲۸: مسیر واقعی ۲۰ مدخل منتخب درس اول؛ پنج جدید در هر جلسه، فلشکارت، انتخاب معنی، جای خالی و اتصال چهار جفت. طراحی اولیهٔ ۸/۴ و انتقال بازی‌ها به مرحلهٔ دوم جایگزین شده است.

## مالکیت و اجرا

[قرارداد تحویل](phase-one-handoff.md) و [typeها](../src/contracts/index.ts) پیش‌نیاز کار موازی‌اند. content مالک `src/content/`، learning مالک `src/learning/` و واگذاری صریح `src/storage/`، ui مالک features/components و سبک‌ها؛ اصلی مالک اسناد، قرارداد، App، PWA، package و تنظیمات. reviewer پس از یکپارچه‌سازی فقط بررسی می‌کند. خروجی هر نقش فایل/رفتار/بررسی/محدودیت دارد.

## پذیرش مرحلهٔ اول

| شناسه | رفتار و شاهد لازم |
|---|---|
| A01 | خانه با درس جاری، شمار موعدها و «ادامهٔ یادگیری»؛ بستهٔ ۲۰ مدخلی جزئی |
| A02 | هر جلسه حداکثر پنج جدید؛ معرفی مجدد/refresh مدخل جدید نسازد |
| A03 | موعدرسیده پیش از خطا/ناتمام و جدید؛ مرورهای تازه پیش از معرفی شروع‌نشده |
| A04 | کارت چرخشی با معنی/مثال/منشأ؛ پشت کارت پاسخ درست یا تسلط نیست |
| A05 | انتخاب معنی و جای خالی معتبر؛ خطا آموزشی و تکرار پس از سه پاسخ دیگر؛ ناکافی برای جلسهٔ بعد |
| A06 | مرور با ساعت کنترل‌شده: +۱، +۳، +۷، +۱۴، +۳۰؛ بدون چندپله در روز یا شناخت/بازی |
| A07 | اتصال دقیقاً چهار جفت، ستون‌های تصادفیِ ماندگار، ثبت هر جفت، رد جفت نادرست/تکراری |
| A08 | هر پاسخ + موعد + feedback + cursor اتمی؛ retry همان attemptId بی‌اثر |
| A09 | refresh/بستن/بازکردن، حفظ draft، pause/resume و خلاصهٔ واقعی |
| A10 | خطای ذخیره بدون پیشرفت کاذب، retry؛ دو تب بدون دو نویسنده، امکان ادامه بعد از آزادشدن |
| A11 | داده/نسخهٔ خراب خطای روشن و حفظ داده، بدون reset |
| A12 | ۳۶۰ و نمای بزرگ بدون پیمایش افقی، لمس/صفحه‌کلید، RTL/LTR/lang، کاهش حرکت، بازخورد مستقل از رنگ |
| A13 | production cache تأییدشده، قطع شبکه و بازشدن دوباره و ادامه/ثبت آفلاین؛ ناقص آماده نباشد |
| A14 | ۲۰ مدخل واقعی گزیده با تمام ارجاعات، مثال تألیفی و برچسب محدودیت بررسی؛ پایان بسته پایان درس نیست |
| A15 | آزمون‌های معنی‌دار موتور/ذخیره، lint/build، مسیر واقعی مرورگر موبایل‌شبیه‌سازی‌شده؛ محدودیت دستگاه واقعی جدا |

نتیجهٔ هر معیار با شواهد در [گزارش پذیرش](acceptance.md) ثبت می‌شود. build به‌تنهایی صحت منبع، اجرای آفلاین یا نصب روی گوشی واقعی را ثابت نمی‌کند. آزمون روی مرورگر دسکتاپ با viewport موبایل با آزمون گوشی فیزیکی یکسان نیست.

## مراحل بعد

۱. بازبینی جامع محتوای درس اول در PDFهای اصل، تکمیل پوشش و سپس درس‌های بعد با هویت مشترک و تداوم مرور.
۲. تمرین نوشتن واژه/آرتیکل، قاعدهٔ تثبیت و هدف زمانی در صورت تصویب و پذیرش جداگانه.
۳. خروجی/بازیابی JSON نسخه‌دار با پیش‌نمایش و جایگزینی اتمی پس از تأیید؛ نمودار و یادآور پس‌زمینه در صورت نیاز.

حساب، بکاند و همگام‌سازی ابری در محدوده نیستند.
