# بررسی تثبیت نسخهٔ فعلی

تاریخ: ۲۰۲۶-۱۰-۲۸. ریشه: `D:\wortzeit\wortzeit`.

**وضعیت: بررسی مستقل انجام شده؛ اصلاح کد و commitها به‌علت ناتوانی محیط در نوشتن index مخزن انجام نشده‌اند. قابلیت آموزشی جدیدی اضافه نشده است.** این گزارش تأیید رفع خطای مرورگر نیست.

## Git و نقطهٔ بازگشت

- پیش از کار، پروژه و والدهای آن مخزن Git نبودند.
- مخزن مستقل با `git init --initial-branch=main .` دقیقاً در ریشهٔ بالا ساخته شد؛ `git rev-parse --show-toplevel` همان مسیر را برگرداند.
- هویت Git از قبل تنظیم بود؛ هویت ساختگی یا تغییر تنظیمات سراسری انجام نشد.
- `.gitignore` برای خروجی‌ها، وابستگی‌ها، cacheها، گزارش‌های آزمون، فایل‌های IDE، `.env*` و کلیدهای خصوصی تکمیل شد. استثنای فایل‌های نمونهٔ env حفظ شد. فایل‌های متنی `reference/vocabulary/`، از جمله منبع لازم برای آزمون محتوا، نادیده گرفته نمی‌شوند.
- بررسی الگوهای رایج کلید خصوصی/توکن در فایل‌های قابل ثبت، نتیجه‌ای پیدا نکرد؛ این بررسی محدود، تضمین جامع نبودن اطلاعات محرمانه نیست.
- `git add -- .` با `Unable to create '.git/index.lock': Permission denied` متوقف شد. index و commit مبنا ایجاد نشدند. این محدودیت مربوط به محیط اجراست، نه نبود هویت Git.
- شاخهٔ فعلی `main` و بدون commit است. نام در نظر گرفته‌شده برای کار اصلاحی `codex/fix-tab-handoff` است؛ هنوز ایجاد نشده است. remote، push و انتشار خارجی انجام نشد.

شرط مستقیم کاربر این است که پیش از اصلاح کد، نسخهٔ موجود در یک commit محلی ثبت شود. چون این شرط هنوز محقق نشده، فایل‌های App، controller، storage و آزمون مرورگر تغییر نکرده‌اند. از مسیر جایگزین برای دورزدن محدودیت نوشتن `.git` استفاده نشده است.

## دو بررسی مستقل، بدون ویرایش فایل

### ایجنت مرورگر

تلاش برای اجرای Chromium با context آزمایشی جدا، پیش از ساخت context با `browserType.launch: spawn EPERM` متوقف شد. هیچ سناریوی دو تب یا دادهٔ مرورگر اجرا/تغییر نکرد. این خطای ابزار است و شکست برنامه محسوب نمی‌شود.

آزمون [browser-test.mjs](../scripts/browser-test.mjs) در سناریوی تب دوم فقط پیام مسدودبودن، بستن تب اول، کلیک retry و انتظار دکمهٔ اصلی را بررسی می‌کند. هنگام timeout، URL، متن بوت، وضعیت `navigator.locks.query()` و خطاهای همان تب ثبت نمی‌شوند. listener خطای صفحه نیز فقط به صفحهٔ اولیه وصل است و به صفحهٔ بازشدهٔ آفلاین و تب دوم تعمیم داده نشده است. بنابراین شاهد فعلی علت دقیق شکست گزارش‌شده را تعیین نمی‌کند.

### ایجنت قفل و راه‌اندازی

در [App.tsx](../src/App.tsx)، درخواست آغازین `ifAvailable: true` است. تب بازنده پیش از خواندن state و ساخت writer متوقف می‌شود. دکمهٔ retry در این حالت فقط `window.location.reload()` را اجرا می‌کند؛ راه‌اندازی بعدی نیز یک درخواست فوری و تک‌مرحله‌ای دارد.

ایجنت با اجرای درون‌حافظه‌ای خودِ App، بدل کنترل‌شدهٔ hooks و LockManager این توالی را نشان داد، بدون ایجاد یا ویرایش فایل:

۱. تب دوم هنگام باقی‌بودن مالک مسدود می‌شود.
۲. retry پیش از آزادشدن مالک دوباره مسدود می‌شود.
۳. آزادشدن بعدی قفل، درخواست تازه‌ای ایجاد نمی‌کند و صفحه مسدود باقی می‌ماند.
۴. retry دیگری پس از آزادشدن، snapshot را با همان draft و شناسهٔ پاسخ بارگذاری می‌کند.

این شاهد، محدودیت retry تک‌مرحله‌ای در صورت contention گذرا را نشان می‌دهد. **ثابت نمی‌کند که Chromium پس از `page.close()` قفل را دیر آزاد کرده یا همین رخداد علت timeout قبلی بوده است.** آزمایش با بدل، اجرای Web Locks در مرورگر واقعی نیست.

## جمع‌بندی هماهنگ‌کننده و ادامهٔ لازم

علت دقیق شکست گزارش‌شده هنوز تأیید نشده است. فرضیهٔ اصلی، درخواست تک‌مرحله‌ای هم‌زمان با آزادشدن قفل است؛ خطای بوت/داده یا فرض انتظار آزمون نیز با شاهد فعلی حذف نشده‌اند.

پس از فراهم‌شدن commit مبنا و محیط مرورگر مجاز:

- خطاهای هر دو تب و صفحهٔ بازشده، متن بوت و وضعیت قفل پیش/پس از retry ثبت شوند.
- بسته‌شدن صفحه از آزادشدن مشاهده‌شدهٔ قفل تفکیک شود. انتظار شرط‌محور برای آزادشدن قفل، در صورت نیاز آزمون، جای تأخیر ثابت یا افزایش بی‌دلیل timeout را بگیرد.
- تا وقتی مالک فعال است، تب دوم نباید writer بسازد یا revision را تغییر دهد.
- پس از آزادشدن، retry و رسیدن به دکمهٔ اصلی بررسی شود؛ revision، پاسخ‌ها، progress، موعدها، queue/cursor و draft قبل و بعد مقایسه شوند.
- اگر محدودیت تک‌مرحله‌ای عامل شکست بود، اصلاح محدود می‌تواند retry صریحِ راه‌اندازی را به درخواست مجددِ قابل لغو در همان صفحه تبدیل کند. این پیشنهاد هنوز اعمال یا در مرورگر تأیید نشده است؛ `steal`، حذف داده و حذف کنترل نویسنده راه‌حل نیستند.
- سپس reviewer مستقل نتیجهٔ اصلاح‌شده را بررسی کند و commit نهایی جدا ثبت شود. این دو مرحله هنوز انجام نشده‌اند.

پاسخ‌ها، تنظیمات مرورگر و اطلاعات محلی پاک نشده‌اند. آمادگی مرحلهٔ آرتیکل و نوشتن واژه، از نظر تثبیت این مورد و پذیرش مرورگر، هنوز تأیید نشده است.
